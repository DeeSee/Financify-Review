# SynchronizationService.swift — Code Review

## Замечания

### 1. Нет механизма предотвращения параллельных синхронизаций
`synchronize()` вызывается из нескольких мест: `BankAccountService.primaryAccount()`, `TransactionsService.getAllTransactions(...)`. Если два ViewModel'а одновременно запрашивают данные, `synchronize()` запустится дважды параллельно. Хотя `SynchronizationService` — actor (последовательный доступ), повторный вызов встанет в очередь и выполнится сразу после первого, что может привести к дублированию запросов (если первый вызов не успел удалить обработанные операции).

**Рекомендация:** Добавить флаг `isSynchronizing` и пропускать повторные вызовы.

### 2. Все 4xx ошибки считаются «фатальными» (строка 53)
```swift
if case .serverError(let statusCode, _) = error, (400...499).contains(statusCode) {
```
409 Conflict, 429 Too Many Requests, 401 Unauthorized — это не фатальные ошибки. 409 может означать конфликт данных (стоит обработать), 429 — стоит повторить позже, 401 — токен протух (стоит обновить).

Сейчас все эти операции молча удаляются из очереди, и пользователь теряет данные.

**Рекомендация:** Дифференцировать обработку: 400/404/422 — фатальные, 401 — обновить токен, 429 — повторить, 409 — стратегия разрешения конфликтов.

### 3. `print()` вместо структурированного логирования (строки 30, 50, 55, 59, 63, 71, 75)
Множество `print()` вызовов для отладки. В продакшене они бесполезны и засоряют консоль.

### 4. Нет уведомления UI о результатах синхронизации
Если операция была отброшена как «фатальная», пользователь не узнает, что его оффлайн-изменение потеряно. Нет обратной связи.
