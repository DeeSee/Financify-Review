# Date+ISO8601.swift — Code Review

## Замечания

### 1. Имя `shmr` (строка 13)
Имя `ISO8601DateFormatter.shmr` — аббревиатура, непонятная без контекста. Предположительно от названия проекта/команды. Для публичного API расширения стандартного типа лучше использовать осмысленное имя, например `withFractionalSeconds` или `financify`.

### 2. `normalizedISO8601` — хрупкая нормализация (строки 3–9)
Метод вставляет `.000Z` если строка заканчивается на `Z` и не содержит `.`. Это работает для конкретного формата сервера, но:
- Не обрабатывает timezone-offset (напр. `+03:00` вместо `Z`).
- Сломается если сервер начнёт присылать другой формат.

**Рекомендация:** Лучше использовать два форматтера (с и без fractional seconds) и пробовать оба.

### 3. `static let` для `ISO8601DateFormatter` — thread safety
`ISO8601DateFormatter` (как и `DateFormatter`) не потокобезопасен. Хотя `static let` гарантирует единственную инициализацию, одновременный доступ из разных потоков к одному экземпляру может вызвать гонку данных. В Swift 6 strict concurrency это будет ошибкой компиляции.

**Рекомендация:** Создавать новый экземпляр в каждом вызове или защитить доступ через actor/lock.
