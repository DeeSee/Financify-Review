# PieChartView.swift — Code Review

## Замечания

### 1. «Остальные» — захардкоженная русская строка (строка 100)
```swift
temp.append((othersSum, "Остальные"))
```
Если приложение будет локализовано, эта строка останется русской.

### 2. `draw(_:)` — сложная логика отрисовки
Метод `draw` содержит ~70 строк с ручной отрисовкой через CoreGraphics: дуги, легенда, текст. Это работает, но:
- Нет кэширования — перерисовка при каждом вызове.
- Нет поддержки Dynamic Type (шрифт захардкожен `fontSize: 12`).
- Нет поддержки Dark Mode для цветов текста (используется `.label` — это ок).
- Легенда может не вместиться если строки длинные.

### 3. `animateUpdate` — потенциальная проблема с timing (строки 49–86)
```swift
self.entities = newEntities  // строка 69 в completion первой анимации
self.prepareSegments()       // дублирует вызов — entities.didSet уже вызвал prepareSegments
```
`entities.didSet` вызывает `prepareSegments()` и `setNeedsDisplay()`. Затем строка 72 вызывает `prepareSegments()` ещё раз. Двойной вызов.

### 4. `segmentColors` — статический массив из 6 цветов (строки 40–47)
Если категорий больше 6, цвета начнут повторяться (`idx % count`). Для финансового приложения с потенциально многими категориями стоит использовать алгоритм генерации различимых цветов.

### 5. `Entity.value: Decimal` — не проверяется на отрицательность
Если `value < 0` (что возможно для итоговых сумм), `percentage` будет отрицательным, и дуга нарисуется в обратном направлении.
